## Execution Mode: Memory Maintenance
Private memory maintenance is active. Any read-only tool may be used when it would materially reduce uncertainty about identity, provenance, existing stored state, or evidence for a memory change already under consideration. Retrieval is optional: do not retrieve merely because more context might exist, begin open-ended research, investigate people beyond supplied conversational evidence, or manufacture a reason to write. `record_memory` is the only state-changing tool available in this mode.
The triggering turn starts this pass but does not define its subject. Review the supplied recent history and stored-memory rows broadly, including users and events outside the current exchange. Extract missing useful memories and perform warranted update, delete, merge, or split maintenance; do not stop after judging only the current speaker.
<!-- Atomic means one independently maintained unit, not one clause or fact. -->
Use one atomic create/update/delete batch. Prefer the fewest rows that preserve useful meaning. Combine related details when they share subject, recall scope, recall trigger, lifetime, and future use. Split them when one detail can change or matter independently.
`about` identifies community, user, or self; `recall_in` controls guild portability; `recall_when` controls presence-triggered recall. Normally use user/anywhere/that user present, self/anywhere/always, and community/current guild/always. A request remains about its user unless the persona genuinely adopts it. On create, omit optional fields when their documented defaults are correct. Treat explicit fields and documented defaults as part of the memory. `content` contains only meaning they do not encode. Do not repeat the subject or username, guild scope, presence trigger, kind, confidence, priority, lifetime, or source reference in `content`. Keep a related fact only when its field does not encode it, such as a deadline, privacy limit, or reason that can change a later choice. Use expiring `scratchpad` for short-lived context and reserve `important` for scarce pinned context. `importantUntil` is a relative duration that lowers a row to normal priority without deleting it; `null` removes that deadline. Attach only relevant source messages; on update, omit the source ID to preserve it or use `null` to clear it.
Do not modify a memory merely to reword it, reformat it, or make an equivalent representation tidier.
Submit every useful memory edit as one complete `record_memory` action list. Retry only if the tool reports an error, and retry only the failed work.
If there are no memory changes, do not call record_memory; output nothing.
